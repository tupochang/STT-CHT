# STT2001 PC 劇情漢化規範

以下規則適用於所有經 `export_batch.py` 匯入、由 `native_caption.cpp` 處理的 `STAGE.DAT` 對話與條件文字。匯出器逐筆套用相同規則，遊戲以原文字碼與前文辨認來源。回報用的 UID 是驗收案例，適用範圍由文字入口與支援的控制碼決定。

| 項目 | 共用規則 |
| --- | --- |
| 來源辨認 | 以完整原文字碼和前方 128 bytes 比對。原文相同、譯文不同時依前文分開。原文及前文均相同而譯文仍衝突時，保留原文並記錄原因。 |
| 短句 | 少於 8 bytes 的來源須緊接在 `FFFD`／`FFFE` 結尾後，且包含可顯示字碼或已支援的姓名變數。索引讀到結尾即停止，仍須核對完整原文和前文。等待確認時，指標須在該短句結尾之後，避免提早顯示下一句。 |
| 姓名變數 | 保留 `[HERO1]` 至 `[HERO4]`。每頁各變數的出現次數必須與原文一致。執行時讀取玩家目前設定的姓名，將姓名字碼與正文納入同一頁的出字進度。姓名欄位或字碼無法辨識時，該頁回退原文。 |
| 翻頁與卷動 | 譯文 `<p>` 必須對應原版 `FFFC`，保持原版頁數及確認時機。等待確認時保留目前頁面，卷動轉換時暫時隱藏中文字，下一頁開始後重設出字進度。 |
| 換行 | 優先保留可容納的原有換行及統一字號。需要重排時，以實測字寬比較當頁的斷行組合，優先在原換行處或標點後分行，並避免拆開英文字及共用詞表中的詞組（如「簡稱」「痕跡」「Number Ten」）。首頁有姓名時正文最多三行，其餘最多四行，並依文字起點限制可用高度。頁面容量不足時允許較不理想的斷點，仍放不下時回退原文並記錄 `page_capacity`。 |
| 多窗口 | 三個對話槽各自匹配、顯示和清除。勝利與敗北條件可同時使用兩個槽位。 |

選單、回合提示、戰鬥等其他文字入口，需確認其來源與顯示流程後再擴充。現階段只允許已解析的控制碼，其他變數與標籤沿用原文。詞組保護依共用詞表擴充。

後續遇到同類漏譯，先核對匯出結果、來源指標、頁面狀態及拒絕原因，再修正共用規則。驗收紀錄分開標示匯出資格、離線檢查和遊戲畫面。對照勝敗條件時須確認實際原句與 UID，例如第一關敗北條件是 U00246。

既有實作與驗收紀錄見[翻頁、換行及多窗口](stt2001_pc_paged_dialogue_fix.md)與[姓名變數及來源辨認](stt2001_pc_name_variables_and_context.md)。
