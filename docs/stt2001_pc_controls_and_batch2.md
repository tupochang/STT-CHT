# PC 劇情第二批、加速與金手指選單

後續共用翻頁、換行及多窗口修正見 `stt2001_pc_paged_dialogue_fix.md`。使用者已確認空白鍵加速及 F1 呼叫可用，金手指效果仍未測試。

日期：2026-11-07。使用者已確認上一版轉場時繁中會消失；本次三項需求為增加翻譯覆蓋、空白鍵切換加速、F1 呼叫金手指選單。

## 使用

關閉舊遊戲，沿用 `powershell -ExecutionPolicy Bypass -File "D:\STT\pc\launch-p1.ps1"`。現在啟動獨立的 `pc/build-runtime/STT2001_PC_Chinese.exe`，存檔路徑維持 `pc/saves-p1/`。

| 操作 | 功能 |
| --- | --- |
| 空白鍵 | 加速開／關，再按一次恢復正常；沿用框架 TurboToggle，預設倍率 4 倍，實際速度取決於效能與框架個人設定 |
| F1 | 開啟／關閉功能選單；開啟時暫停遊戲並攔截遊戲按鍵 |
| ↑／↓ | 選取金手指 |
| Enter | 切換所選且受支援的金手指 |
| Esc | 關閉選單、返回遊戲 |

選單內不把空白鍵傳給加速器；返回遊戲後再切換。現階段鍵盤操作，未實作滑鼠／手把選單導航。

## 金手指

來源為現有本地 `tools/duckstation-diagnostic/resources/cheats.zip` 的 `SLPS-02863.cht`。代碼原樣保存到 `pc/stt2001.cht`，僅翻譯項目名稱，未從其他遊戲套用地址。

可切換 6 項：男主角 HP、女主角 HP、假面騎士 HP、假面騎士人形 HP、金錢、全部道具。預設全部關閉，每次啟動重設為關閉；關閉會停止持續寫入，已改變的遊戲數值不會自動恢復。

傷害修改、音樂影片全開、圖鑑全開共 3 項顯示「不支援」，禁止啟用。前者修改原版指令，後兩者使用尚未解析的代碼型態；直接寫入原 MIPS 指令也不能保證影響已重編譯的主程式。

`cheat_engine.h` 支援 80 半字、90 字、30 位元組 RAM 寫入，以及 D0／D1 的下一條件判斷；拒絕未支援型態、不對齊、超出 2 MB RAM，以及主執行檔程式範圍。任一列不支援則整項禁止。每幀於 CPU 執行緒從既有 `0x800150E8` 觀察器呼叫，使用框架 host write API；未改 BIOS、原光碟或框架核心。F1 暫停時不跑 guest 幀，開關在返回遊戲後開始作用。

這代表代碼已匯入且執行器可處理，**尚未驗證六項在遊戲畫面中的效果或不同角色／關卡相容性**。不宣稱全數原版 PS 金手指都可用。

## 檢查與限制

- 建置：新的獨立 EXE 編譯連結通過。未停止使用者當前遊戲程序。
- 使用真實框架 `host_keymap.c`／SDL3 測試 `config.ini`，Space 對應 TurboToggle；框架現有邏輯只在非 repeat keydown 翻轉狀態。
- 選單探測以合成 SDL 事件檢查 F1 暫停／輸入捕捉、長按不重複開關、Space 在選單外傳遞、選單內切換、退出恢復及所有項目預設關閉。
- 以原代碼確認六項可解析，開啟男主角 HP 產生三次 16-bit／999 寫入，關閉後不再寫入；條件成立／不成立及程式區拒絕測試通過。
- 在隱藏 OpenGL 3.3 core 視窗呼叫實際選單 renderer：2,663 個高亮 pixels、6,848 個亮色文字 pixels、GL error 0；已人工查看生成選單圖確認文字未裁切。這是介面測試，沒有冒稱遊戲內 F1 驗收。
- 9,896 筆進度表檢查通過；合成 RAM 驗證 U00213 姓名不隱藏、正文向下 16 遊戲 pixels、姓名期間繁中進度為零、正文能漸進。
- 既有原框、透明背景、X 隱藏／恢復、全畫面亮度與場景關閉回歸通過。逐字仍按來源節奏比例映射。

遊戲內下一次檢查可用空白鍵快速到達此次對話：確認正文出現繁中、姓名與頭像保留、換行不出框；再試 F1 的暫停／返回及個別金手指。不需要從頭以正常速度重播。
