# PC 共用翻頁、換行及多窗口修正

2026-11-07。使用者確認空白鍵加速與 F1 選單可以使用；金手指效果尚未測試。使用者要求將同類漏譯一次修正到其他段落，故本次修改共用機制，沒有為每句另加顯示條件或改寫 Excel。

## 已定位的原因

| 回報畫面 | 對應／證據 | 原因 |
| --- | --- | --- |
| SIDO 英文全稱旁白 | U00211 已列入 pack，但遊戲日誌沒有 matched | 原譯文單行超寬，舊 `fits` 整段回退 |
| 長官質疑 SIDO 要塞艦 | U00215 已列入 pack，日誌跳至 U00216 | 同樣為單行超寬；已用實際 x=72／y=154 檢查新換行 |
| 日向博士 Number Ten、長官後續多頁發言 | U00221、U00222、U00224 等，原資料含 FFFC、譯文含 `<p>` | 舊匯出器將整段排除；狀態觀察器也沒有接受等待翻頁的狀態 1 |
| 勝利／敗北條件只有上框繁中 | U00243／U00244；原觀察器匹配第一個槽位後便停止 | 全域只有一份 caption 狀態，無法同時顯示兩框 |
| 回合提示、能力頁 | 尚未建立該入口的繁中繪製與控制映射 | 本次仍未覆蓋，不視為以上修正的驗收項 |

原版靜態證據：`0x8004BCC4–0x8004BCCC` 將 FFFC 設為狀態 1，經 `0x8004BCEC–0x8004BCF8` 把來源指標移到下一頁。對話更新表 `0x80010C7C` 的狀態 1 入口為 `0x8004A258`；確認後呼叫 `0x8004D2F4(a1=0)` 設狀態 2，再由 `0x8004C2A4` 處理轉換。因此「指標已到下一頁」不能直接解讀成下一頁已開始顯示。

## 共用修正

1. 匯出器允許 `<p>` 與來源 FFFC，逐段核對頁數，其他未支援標籤／角色變數繼續拒絕。移除必須同一行數的資格限制；完整來源特徵、前文核對和同來源譯文衝突保護保留。
2. `caption_pages.h` 建立來源各頁的起訖。狀態 1 且指標剛好跨過 FFFC 時保持上一頁全文，狀態 0 才選取下一頁並將進度歸零。4／5 保留最後頁，6／關閉清除；往回讀檔可從指標重新選頁。
3. 狀態 2／3 轉換期間暫時隱藏中文字，回到狀態 0 後重建下一頁。**沒有仿製原版逐像素卷動動畫**，需實際遊戲確認此過渡是否合適。
4. `caption_reflow.h` 以 Microsoft JhengHei 實測字寬重排當頁。原排版可容納時保持原行；否則保留英文字邊界、避免部分閉合標點行首、以既有字號換行。只重排原頁，沒有新增確認次數、改劇本頁數或縮小字型。
5. 首頁若有姓名保留姓名行，正文向下 16 遊戲 pixels；後續頁從原文字起點開始。最多四行、首頁有姓名時正文最多三行，並受畫面底部限制。仍放不下時保留日文，新增一次性 `rejected Uxxxxx page=... reason=page_capacity` 診斷，避免無聲回退；相同失敗排版會快取。
6. 保留原排版與行數時沿用逐行進度；重排後以當頁來源字數比例映射繁中進度。姓名字碼仍不計入正文，原版輸入／週期繼續執行。
7. 三個原對話槽分別保存字層狀態、進度、排版和像素，逐槽繪製／清除。來源 glyph 隱藏也按槽位限定；一框關閉不清除另一框。全畫面亮度及已確認的旁白 X 分支同步套用三槽。

這些變更會作用於其他使用同類 STAGE 字碼和控制流程的段落，並非只修 U00211 或 U00221。角色變數、彩色標籤、一般選單入口仍需個別支援，不能宣稱全遊戲畫面已完成。
