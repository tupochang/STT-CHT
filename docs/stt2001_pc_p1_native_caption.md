## 原框透明字型實驗版（待畫面驗收）

後續使用者畫面確認：`codex-clipboard-4a8b603c-0833-49dd-85b9-e5cb46e75b28.png` 顯示繁中已在原框內、原日文不再疊印、背景紋理與邊框保留，且寬視窗的置中位置可用。`codex-clipboard-b94ab8e8-81a0-4181-8c8c-62924d33b549.png` 同時暴露按 X 隱藏窗口後繁中仍停留的問題；不能把原框顯示成功擴大成隱藏功能通過。

已保留使用者驗證過的進度字幕版 EXE 為本機 `STT2001_P1_ProgressPanel_baseline.exe`。新版本仍只處理 U00208。

`0x8004A0D8` 的初始化和 `0x8004B92C` 的字形位置寫入，均可確認對話槽 `+6`、`+8` 為起始文字 X／Y。PC 文字依這兩個欄位定位，按 320×240 的 4:3 畫面置中縮放，每行採原版 16 像素行距。面板改成透明文字層，不覆蓋原版窗口背景及邊框；行寬目前針對此旁白取至畫面右側內縮 16 像素，尚非全遊戲視窗寬度模型。

日文字形查找 `0x8004A7D8` 的輸出結構：`+8` 是 8／12 像素字寬，`+0xA` 是 16 像素字高。新鉤子只在 U00208 啟用、PC 字型繪製器就緒且返回位址為 `0x8004BDB0`（此劇情繪字呼叫點）時，先執行原版查找，再將該字形高度設為 0。字寬、CPU 返回值及原版週期仍由原函式提供；其他呼叫者回退原版。修改的是遊戲運行時字形物件資料，不是 ISO、生成碼或 BIOS。

標題畫面的 OpenGL 執行緒預熱字型繪製器後釋放暫用的 overlay provider，正常文字繼續由 HUD 層顯示；未就緒或來源座標不合理時保留日文與下方字幕回退。記錄 `STT_P1 core font renderer ready before dialogue` 和 `STT_P1 layout ... in_frame=1` 可用來確認該路徑是否啟用。

本機核心模式回歸檢查：透明原框文字有 7,330 個文字像素、55,134 個原背景像素保留、目標範圍外白色像素為 0；寬螢幕置中座標檢查通過，GL 錯誤為 0。字形鉤子探測確認原函式被呼叫、字寬 12 和返回值 16 保留、只把字高改成 0，其他返回位址不攔截。這些檢查不等於實際遊戲物件已正確隱藏；日文是否完全消失、繁中位置是否合適及換段恢復，仍需 U00208 的實際畫面驗收。

## 隱藏窗口跟隨修正（待遊戲內驗收）

原版旁白控制分支 `0x80021DDC` 在隱藏輸入成立時呼叫 `0x80016DE0(4)`，返回位址為 `0x80021DF8`，並跳過文字更新；正常分支呼叫 `0x80016DE0(1)`，返回位址為 `0x80021E08`，再呼叫對話更新。`0x80016DE0` 將參數寫到 `$gp+0x338`；原版繪製器讀取該值選擇繪製列表組。故槽位仍啟用／指標未變不代表窗口仍顯示，舊 HUD 沒有收到清除事件。

新增唯讀觀察該選擇函式，限定這兩個旁白返回位址與對應參數：組 4 隱藏 PC 字層，組 1 恢復字層，保留文字進度並讓原版函式繼續執行。不監聽 Windows 鍵盤 X，不自行複製按鍵邏輯，也不把其他繪製列表設定誤當成隱藏。

核心模式回歸：隱藏後文字像素為 0、恢復後回到 7,330 個、文字進度保留；無關呼叫位址不改變顯示狀態。這證明回呼／渲染路徑的隱藏恢復可用，原版實際按鍵分支是否命中仍需遊戲驗收。新診斷為 `STT_P1 presentation visible=0/1 chars=...`。

## 文字進度與清除實驗版

保留已驗證的整段字幕 EXE 為本機 `STT2001_P1_FullCaption_baseline.exe`，新版本仍由 `launch-p1.ps1` 啟動。整段字幕的畫面驗證不自動延伸到本次改動。

原版 MIPS 靜態證據：`0x8004A1C4` 每次更新檢查 3 個對話槽；各槽從 `0x800C6B88` 起、間隔 44 B，`+0` bit0 是啟用門檻，`+0x10` 是狀態，`+0x20` 是文字指標。`0x8004B92C` 讀取該指標，普通字與換行處理後前進 2 B。`0x8004BCDC/0x8004BCEC` 將 `FFFD` 設為狀態 4 並前進指標。因此 U00208 的指標恰好移到 `base+108` 時仍可能等待玩家確認，不能直接將它解讀為下一段已開始。

新增唯讀的對話更新入口觀察，按每幀槽位快照重建面板狀態。狀態 0 顯示進度；狀態 4／5 保留已完成文字；未啟用、其他狀態或換成不同文字則隱藏。這是針對 U00208 的最小模型，其他控制碼與場景不假設相同。按原文逐行的字數進度比例映射繁中前綴；不使用牆上時鐘、不改遊戲速度。原文與中文長度不同，因此它是「原文節奏映射」，不是逐個中文字獨立計時。來源行數不符或有未支援控制碼時拒絕映射並回退日文。

`caption_progress.h` 的回歸探測通過行進度、FFFD 後等待、關閉、替換、奇數指標拒絕、進度回退與行數不符拒絕；更新後的實際繪字程式也通過 3.3 core 渲染探測。這些是離線檢查；遊戲內的漸進出字、按鍵一次顯示全文、翻頁與存讀檔仍待實測。下一次畫面驗收只需看原本同一段 U00208，記錄是否漸進顯示、全文是否保留到確認，以及確認後是否清除。
